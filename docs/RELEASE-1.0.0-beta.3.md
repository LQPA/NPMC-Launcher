# NPMC Launcher 1.0.0-beta.3（预发布）

> **状态：草稿，尚未发版。** 内容对应 `main` 上 beta.2 之后的全部改动，
> 发版时按 `docs/HANDOFF-2026-11-08.md` §18.1 的流程执行，并把本文件正文作为 release body。

第三个公开测试版。Windows x64 单文件，自带 .NET 运行时，**不需要安装任何前置**
（不需要装 .NET，也不需要装 Java —— 游戏运行时由启动器自动下载）。

## 相对 beta.2 的变化

### 实例隔离

- **设置页可选隔离级别**：「版本隔离（推荐）」与「完全隔离」两项。
  选中后**不会立即生效**，会先显示确认条说明影响范围，点「确认更改」才写入设置；
  `Full` / `Version` 枚举值保留，界面上不再提供"不隔离"选项（避免新建实例继续踩共享目录）。
- **已有"不隔离"实例可一键迁移**：实例概览对该类实例显示红色提示 + 「改为版本隔离」。
  第一次点只显示将复制多少文件、多少 MB，**再点一次才动文件**（10 秒不点自动取消）；
  迁移会把共享根里的 `mods / config / resourcepacks / shaderpacks / saves / defaultconfigs / scripts`
  以及 `options*.txt`、`servers.dat` **复制**进实例目录（共享目录原文件保留，其它实例不受影响），
  然后才切换隔离级别。
- 新建实例（下载页、整合包安装）使用设置里的默认级别；复制实例继承源实例的级别。

### 整合包预设启动参数

- 导入整合包时读取作者预设的 **JVM 参数**与**一键进服地址**，来源优先级：
  `instance.cfg` 的 `OverrideJavaArgs` + `JvmArgs` → 包根 `.nmpc-pack.json`
  （`jvmArgs` 支持字符串或数组、`quickPlayServer`）→ 包内 `options.txt` 的 `quickPlayMultiplayer:`。
- 导入计划里**只提示一次**，列出参数原文与进服地址；安装时写进实例设置，
  **实例已有自定义参数则不覆盖**。
- 一键进服按游戏版本生成参数：1.20+ 用 `--quickPlayMultiplayer host:port`，更老的版本用 `--server host --port p`。
- 导出侧反向写回：MultiMC 包写入 `instance.cfg`，mrpack / CurseForge 包写入包根 `.nmpc-pack.json`，
  导出 → 导入可闭环。

### 导出

- **高级导出选项**新增「包含实例 JVM 参数」（默认勾选）与「追加 JVM 参数」（一行文本，留空不追加）。
- 合并规则：完全相同参数去重；`-Xmx / -Xms / -Xss / -XX:MaxHeapSize` 同键时后者生效；
  合并结果如实写进导出状态，不再静默丢弃。
- 导出摘要**如实反映**这次是否真会把 JVM 参数写进包（都没勾、没填时显示「JVM 参数不写进包」）。
- 修掉一个布局问题：「高级导出选项」与 JVM 参数块一度放在"是否为整合包导出"的判断里，
  选择 MultiMC 格式时整块消失；现在三种格式都能看到，打包规则块仍只在 mrpack / CurseForge 时显示。

### 内存

- **整合包要求的 `-Xmx` 按本机极限值夹紧，而不是直接丢弃**：
  本机极限值 = `min(物理内存 − 2048 MB, 物理内存 × 75%)`。

  | 情况 | 结果 |
  | --- | --- |
  | 整合包 `-Xmx` ≤ 极限值 | 原样使用（保留作者的值） |
  | 整合包 `-Xmx` > 极限值 | 夹紧到极限值 |
  | 整合包没写 `-Xmx` | 用自动值 |

  - 只改 `-Xmx` / `-Xms`（`-Xms` 压到 `min(夹紧值, 512M)`），其它 JVM 参数原样保留；
  - 夹紧时弹一次启动诊断卡片「内存已按本机情况调整」，同时写进 `logs/launcher.log`；
  - 判定只用物理内存，当前空闲内存只写进提示文字，避免同一配置每次结果不同。
- 整合包的推荐内存与「自动内存」的关系保持 beta.2 的折中规则：勾了自动就保持自动，
  预设值作为自动值的下限（`MemoryFloorMb`）。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 1607+ / Windows 11，**x64** |
| 运行时 | 无需安装（exe 自带 .NET 8 运行时，不依赖 VC++ 运行库） |
| 位置 | 放在**可写目录**（会在 exe 旁创建 `data/`、`minecraft/`、`runtime/`） |
| 网络 | 首次安装游戏 / Java 需要联网 |

放 `Program Files` 会因权限失败；`%TEMP%` 被策略禁用时启动不了（单文件需要解压原生库）。

## 已知限制

- **联机（P2P）入口目前置灰**，代码保留但不开放。
- 未做代码签名：别的机器首次运行会提示"未知发布者"。
- 「改为版本隔离」的迁移**只在逻辑层验证过**，尚未在真实实例上跑过；迁移采用复制（不删源），
  共享目录原文件保留，但文件量大时耗时会比较久。
- 公共翻译端点按 IP 限流，额度不公开；触发限流时只会显示原文或缓存译文。
- 搜索标签分类仍偏宽（Modrinth 的 `technology` 标签），暂未细分。
- 整合包更新检查的"平台优先"只对整合包自带的模组生效，用户手动添加的模组始终两个平台都查。

## 快速开始

1. 双击 `NPMC.Launcher.App.exe`；
2. 「下载」页选择游戏版本 → 点「下载并创建实例」（首次会自动下载本体与 Java 运行时）；
3. 想装整合包：下载页切到「整合包」，在线搜索或把 `.mrpack` / `.zip` / MultiMC 实例包拖进页面；
4. 启动失败时看「日志」页或实例概览里的诊断卡片，`logs/launches/<时间>/` 里有完整归档。

## 校验

发布页附带 `SHA256SUMS.txt` 与 `NPMC.Launcher.App.exe.sha256`，与 exe 同名同目录即可校验：

```powershell
Get-FileHash .\NPMC.Launcher.App.exe -Algorithm SHA256
```
