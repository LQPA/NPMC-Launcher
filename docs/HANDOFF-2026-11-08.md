## 3. 本次完成的诊断功能

### 3.1 启动前诊断

新增文件：

```text
src\NPMC.Launcher.App\Diagnostics\LaunchDiagnostics.cs
src\NPMC.Launcher.App\Diagnostics\LaunchLogSession.cs
```

实例概览顶部会出现诊断卡片，覆盖：

- 版本未安装
- Java 运行时问题
- 启动条件不满足
- 启动异常
- 异常退出后的日志分析

### 3.2 每次启动独立归档

每次真正启动游戏时创建：

```text
<launcher-root>\logs\launches\<yyyyMMdd-HHmmss>-<实例名>\
  launch.json
  README.txt
  latest.log
  nmpc-stderr.log
  nmpc-stdout.log
  nmpc-command.txt
  crash-reports/        # 仅当本次生成原生 crash-report
  crash.log             # 异常时生成的可读汇总
  result.json           # outcome=normal/crash、exit_code
  diagnosis.txt
```

关键行为：

- `latest.log` 仍是 Minecraft 的活动日志；
- 退出时复制到会话目录，按本次启动时间过滤；
- 诊断读取会话快照（`AnalyzeSession`），不读实例目录里可能过期的 live 文件；
- 正常会话保留最近 10 次，异常会话保留最近 50 次；
- 没有原生 crash-report 时不创建空的 `crash-reports`；
- `README.txt` 解释各文件；
- `crash.log` / `diagnosis.txt` 使用 UTF-8 BOM。

### 3.3 崩溃诊断规则

`LaunchDiagnostics.cs` 当前覆盖：

- 缺少前置模组
- 模组重复
- Mixin 冲突（仅真正 fatal，不再把可选兼容目标的 WARN 当冲突）
- Java 版本
- 内存不足
- 图形/OpenGL
- 登录凭据
- 文件缺失/损坏
- jar 损坏
- 模组加载失败
- `NoClassDefFoundError`
- Mixin 版本不兼容

结构化解析：

- crash-report 的 `-- MOD ... --`
- `Mod File:`
- `Failure message:`
- `Currently, ... is not installed`
- `Mixing ... from mixins.xxx.json into ...`
- `Class version ... required ... Mixin supports ...`

### 3.4 详细诊断启动

诊断卡片按钮：

```text
详细诊断启动
```

会追加：

```text
-Dmixin.debug=true
-Dmixin.debug.verbose=true
-Dmixin.debug.export=true
-Dmixin.checks.interfaces=true
-Dforge.logging.mixin.debug=true
```

并额外归档：

- `.mixin.out/`
- `logs/debug.log`
- `hs_err_pid*.log`

然后用户可点“查看崩溃日志”打开 `crash.log`，或“导出日志”生成 ZIP。

### 3.5 实测过的案例

- 故意移走 `26.1.2.json`：卡片显示“游戏版本未安装”。
- 伪造缺前置 crash-report：卡片显示“缺少前置模组”。
- 真实 Oculus 案例：详细诊断中找到：

```text
Mixing MixinRenderTarget from mixins.oculus.json
into com.mojang.blaze3d.pipeline.RenderTarget

Class version 61 required is higher than the class version supported by Mixin
(JAVA_8 supports class version 52)
```

结论：Oculus 的 Mixin 与当前加载器/版本不兼容，不是 Mekanism/Sodium 的可选目标 WARN。

## 4. 模组删除后的列表刷新

已修复一个 UI bug：

## 5. 当前已知限制

- 诊断仍是规则/日志启发式，不是完整的模组元数据依赖图；
- 尚未建立“类名 → 模组 jar”索引，因此某些 `NoClassDefFoundError` 只能报类名/症状，不能百分百点名模组；
- 详细诊断依赖 Mixin verbose/export，日志可能较大；
- 原生 crash-report 不存在时，`crash-reports` 为空是正常的，信息在 `crash.log`；
- 旧版导出的 ZIP 不会自动修复，重新启动生成新会话后再导出。

## 9. 2026-11-08 晚：本会话补充（诊断分级 + 实例页 + 发布脚本）

### 9.1 诊断改成"证据分级"

`LaunchDiagnostics.AnalyzeTexts` 的判定顺序现在是固定的阶梯，**不再是哪条正则先命中听谁的**：

1. 崩溃报告的结构化缺失依赖（`-- MOD --` 段 / `Missing and unsupported mandatory dependencies`）
2. 与 mods 目录交叉校验：**jar 在、加载器却说"未安装"** ⇒ 是该模组自己加载失败
3. 崩溃点之前最近的一条 `Error loading class` / `NoClassDefFoundError` + 包名反查
4. Mixin 注入失败 / Class version 警告 ⇒ 只作次生症状
5. 其余正则兜底

实测结论（13:45 的真实归档）：Oculus 的 `Class version 61 vs JAVA_8(52)` 是**噪声**，
真因是缺 Sodium/Embeddium 提供的 `net.caffeinemc.mods.sodium.api.*`。
报告现在输出「缺少前置：Sodium / Embeddium」，并把 Mixin 警告折叠进次生症状。

配套新增 `Mods/ModMetadataIndex.cs`：读 jar 内 `mods.toml` / `neoforge.mods.toml` / `fabric.mod.json` /
`quilt.mod.json`，区分 mandatory 与 optional；按 (文件名, 大小, mtime) 缓存到 `<root>\cache\mod-index.json`。

### 9.2 启动归档

  它里面才有 `RaiseCommandStates()` / 概览字段重算。

### 9.4 整合包安装

- Fabric 预检：`meta.fabricmc.net` 对 **26.x 的每条 loader 都写 `intermediary=0.0.0`**（26.1.2/26.2/26.3/26.4-快照
  全都一样），而 1.x 写的是游戏版本号。旧代码把 0.0.0 当"不支持"过滤 → 26.x 全灭。
  现在：**全部是占位符时按全量返回**，真正的可装性交给 `profile/json` 判定。
- Quilt 同样加了 `TryCheckInstallableAsync`；Forge / NeoForge 提前 `PrepareAsync`（只下几 MB 安装包）做预检。
- 三者都在**下载游戏本体之前**失败，不再白下 86 MB。

### 9.5 发布脚本

`tools\publish.ps1`：
- 目标 exe 被占用时先 `CloseMainWindow`，3 秒不退再强杀（开发阶段允许），仍占用则明确报错；
- 复制后用 SHA256 对比 staging 与目标，不一致直接抛错 —— 修掉"脚本说完成、E: 还是旧版"；
- **文件必须保持 UTF-8 BOM**：无 BOM 时 PowerShell 5.1 按 ANSI 读，中文串里的字节会吃掉后面的引号，直接语法错误。

### 9.6 事故记录：ViewModel 被编码往返损坏

本次会话有一次 `Get-Content -Raw` / `Set-Content -Encoding utf8` 的往返，把
`ViewModels\MainWindowViewModel.cs` 全部中文变成乱码，其中 1313 处字节丢失。
恢复方式：GBK 双字节对 → 原 UTF-8 逆运算（98.7%），剩余空洞按上下文逐处补齐。
**结论：改源码不要用 PowerShell 的文本往返；用编辑器/写入工具，或显式 `[IO.File]::ReadAllText(path, UTF8)`。**
