## 3. 本次完成的诊断功能

### 3.1 启动前诊断

新增文件：

```text
src\NPMC.Launcher.App\Diagnostics\LaunchDiagnostics.cs
src\NPMC.Launcher.App\Diagnostics\LaunchLogSession.cs
```

实例概览顶部会出现诊断卡片，覆盖：

- 版本未安装
- Java 运行时问题
- 启动条件不满足
- 启动异常
- 异常退出后的日志分析

### 3.2 每次启动独立归档

每次真正启动游戏时创建：

```text
<launcher-root>\logs\launches\<yyyyMMdd-HHmmss>-<实例名>\
  launch.json
  README.txt
  latest.log
  nmpc-stderr.log
  nmpc-stdout.log
  nmpc-command.txt
  crash-reports/        # 仅当本次生成原生 crash-report
  crash.log             # 异常时生成的可读汇总
  result.json           # outcome=normal/crash、exit_code
  diagnosis.txt
```

关键行为：

- `latest.log` 仍是 Minecraft 的活动日志；
- 退出时复制到会话目录，按本次启动时间过滤；
- 诊断读取会话快照（`AnalyzeSession`），不读实例目录里可能过期的 live 文件；
- 正常会话保留最近 10 次，异常会话保留最近 50 次；
- 没有原生 crash-report 时不创建空的 `crash-reports`；
- `README.txt` 解释各文件；
- `crash.log` / `diagnosis.txt` 使用 UTF-8 BOM。

### 3.3 崩溃诊断规则

`LaunchDiagnostics.cs` 当前覆盖：

- 缺少前置模组
- 模组重复
- Mixin 冲突（仅真正 fatal，不再把可选兼容目标的 WARN 当冲突）
- Java 版本
- 内存不足
- 图形/OpenGL
- 登录凭据
- 文件缺失/损坏
- jar 损坏
- 模组加载失败
- `NoClassDefFoundError`
- Mixin 版本不兼容

结构化解析：

- crash-report 的 `-- MOD ... --`
- `Mod File:`
- `Failure message:`
- `Currently, ... is not installed`
- `Mixing ... from mixins.xxx.json into ...`
- `Class version ... required ... Mixin supports ...`

### 3.4 详细诊断启动

诊断卡片按钮：

```text
详细诊断启动
```

会追加：

```text
-Dmixin.debug=true
-Dmixin.debug.verbose=true
-Dmixin.debug.export=true
-Dmixin.checks.interfaces=true
-Dforge.logging.mixin.debug=true
```

并额外归档：

- `.mixin.out/`
- `logs/debug.log`
- `hs_err_pid*.log`

然后用户可点“查看崩溃日志”打开 `crash.log`，或“导出日志”生成 ZIP。

### 3.5 实测过的案例

- 故意移走 `26.1.2.json`：卡片显示“游戏版本未安装”。
- 伪造缺前置 crash-report：卡片显示“缺少前置模组”。
- 真实 Oculus 案例：详细诊断中找到：

```text
Mixing MixinRenderTarget from mixins.oculus.json
into com.mojang.blaze3d.pipeline.RenderTarget

Class version 61 required is higher than the class version supported by Mixin
(JAVA_8 supports class version 52)
```

结论：Oculus 的 Mixin 与当前加载器/版本不兼容，不是 Mekanism/Sodium 的可选目标 WARN。

## 4. 模组删除后的列表刷新

已修复一个 UI bug：

- 删除模组只从列表移除行，没有重新扫描 `mods`；
- `_contentFileTotal` 保留删除前数量；
- 空列表提示会错误显示“已折叠 N 个整合包自带模组”。

修复：`DeleteAsync` 后执行 `RefreshContentAsync()`。

被删除的模组实际在：

```text
mods\.trash\<时间戳>-<文件名>
```

`.trash` 被 ContentScanner 跳过；可以从这里恢复。

## 5. 当前已知限制

- 诊断仍是规则/日志启发式，不是完整的模组元数据依赖图；
- 尚未建立“类名 → 模组 jar”索引，因此某些 `NoClassDefFoundError` 只能报类名/症状，不能百分百点名模组；
- 详细诊断依赖 Mixin verbose/export，日志可能较大；
- 原生 crash-report 不存在时，`crash-reports` 为空是正常的，信息在 `crash.log`；
- 旧版导出的 ZIP 不会自动修复，重新启动生成新会话后再导出。
